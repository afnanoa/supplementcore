Category taxonomy (SKOS)

Products are filed under their most specific category. Queries walk up the hierarchy, so a search for Vitamin also finds B-vitamin and fat-soluble-vitamin products.

Modeling choices

FeatureHow it's used
Property inheritancehasActiveIngredient and hasInactiveIngredient are sub-properties of hasIngredient, so one query returns every ingredient.
Inverse propertiesThe data says which company makes a product; the reasoner adds what each company manufactures.
Defined classesPregnancyCautionSupplement and AdultOnlySupplement are never tagged by hand. The reasoner classifies products into them.
Structured dosesEach dose has an amount and a unit (g, mg, mcg), so rules and queries can convert and compare them.
Vocabulary alignmentClasses and properties map to Schema.org and Dublin Core, and query 8 exports products as Schema.org data.

Validation catches real errors

The sample products pass. Two broken records contain eight planted errors, and the SHACL rules catch all eight, including one plain SHACL can't express. This SPARQL-based rule converts both doses to mg and rejects a record whose recommended dose is above its maximum:

SELECT $this ?rec ?max
WHERE {
  $this sc:recommendedIntake ?r ; sc:maximumIntake ?m .
  ?r sc:amount ?ra ; sc:unit ?ru .
  ?m sc:amount ?ma ; sc:unit ?mu .
  BIND (IF(?ru = "g", ?ra * 1000, IF(?ru = "mcg", ?ra / 1000, ?ra)) AS ?rec)
  BIND (IF(?mu = "g", ?ma * 1000, IF(?mu = "mcg", ?ma / 1000, ?ma)) AS ?max)
  FILTER (?rec > ?max)
}

Result: "Recommended intake (2000.0 mg) is higher than maximum intake (500.0 mg)." See the full validation report.

Background

This builds on supplementCore, an 18-element XML metadata schema I co-designed for Metadata Theory and Practice at the University of Illinois Urbana-Champaign (MS in Library and Information Science, 2023). The original checked the format of individual XML records. This version models the same domain as linked data, so it can be reasoned over, validated across records and queried.
